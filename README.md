# Checkys

Система мониторинга состояния сотрудников: web-клиент (мобильный интерфейс + панель HR) и REST API.
Без внешних зависимостей: нужен только **Node.js 18+**.

## Запуск
```
cd checkys
node server.js        # или: npm start
```
Откройте http://localhost:3000. При первом запуске создаются демо-данные (папка `data/`).
Переменные окружения: `PORT` (3000), `MAX_LOGIN_TRIES` (5; после этого вход блокируется на 15 минут).
Чтобы сбросить данные, остановите сервер и удалите папку `data/`.

## Показ и демо-режим
`start-demo.bat` / `start-demo.sh` запускают сервер с `DEMO=1`: на экране входа появляются кнопки быстрого входа и сброс данных. Подробности, подключение телефона и Expo Go: **ДЕМО.md**; оболочка для Expo Go: `mobile/App.js`.

## Структура
- `server.js` — бэкенд: аутентификация, роли, изоляция предприятий, тестирование, запись, семинары, агрегаты для HR.
- `public/index.html` — фронтенд (HTML/CSS/JS), работает только через `/api/v1`.
- `data/db.json` — хранилище (создаётся автоматически), `data/secret.key` — ключ подписи токенов.

## Что реализовано на сервере (ТЗ)
- Пароли — scrypt с солью; токены HMAC, 12 ч; смена пароля и выход отзывают старые сессии (AUTH-07).
- Ограничение попыток входа (AUTH-06), принудительная смена временного пароля (AUTH-04) и согласие на обработку данных — проверяются на сервере для каждого запроса.
- `organization_id` берётся только из учётной записи, не из запроса; HR видит и меняет только своё предприятие (п. 11.1).
- Тесты версионируются; результат хранит версию методики и категорию, расчёт делает сервер.
- Панель HR получает только агрегаты; группы меньше 5 человек не раскрываются; индивидуальных результатов и записей к психологу у HR нет.
- Квота 4 консультации в год, занятые слоты скрываются, аудит действий HR (`GET /api/v1/hr/audit`).

## API
`POST /auth/login|logout|password` · `GET|PATCH /me` · `GET /tests/available` · `POST /test-sessions`, `/{id}/answers`, `/{id}/complete` · `GET /results/history` · `GET|POST /goals` · `GET /specialists` · `GET|POST /appointments`, `PATCH /appointments/{id}` · `GET /seminars`, `POST /seminars/{id}/response` · `GET /hr/summary|employees|seminars|audit`, `POST /hr/employees|seminars`, `PATCH /hr/employees/{id}`.

## Ограничения (для боевой версии)
Вместо JSON-файла нужна PostgreSQL; нужны HTTPS, push-уведомления, роли «специалист» и «системный администратор», выгрузка отчётов. Вопросы теста и пороги категорий — демонстрационные, их заменяет утверждённая методика (`TEST` в `server.js`).
